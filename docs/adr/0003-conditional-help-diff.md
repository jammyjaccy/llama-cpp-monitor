# 条件 help-diff：仅在判定有正提升时下载二进制

「新增命令」检测以文本扫描（release/commit 文本中的 `ADD --xxxx` 类字样）为默认手段；仅当某版本被 LLM 判定对用户本地有正提升时，才下载该版 Windows 二进制跑 `--help` 与上一版 diff，作为更权威的第二来源。

**考虑过的方案**：① 每版都下载二进制做 help-diff（最准，但每版多下载几十 MB、执行外部二进制，3-4 版/天频率下代价高）；② 纯文本扫描（零下载，但漏报误报多）。

**为什么条件触发**：help-diff 的价值集中在「值得关注的版本」上；条件触发把下载成本限制在有正提升的版本（预期少数）。已知取舍：下载失败不重试（增量任务不会回头处理旧版本），该版新增命令仅靠文本来源兜底，页面标注「help diff 未完成」。
