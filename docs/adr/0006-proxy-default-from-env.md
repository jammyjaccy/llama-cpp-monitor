# GitHub 访问代理默认值改由项目 .env 提供

`proxy`（GitHub 访问代理，完整 URL）的默认值由项目 `.env` 的 `PROXY` 键提供，不再硬编码在代码里。配置优先级与 ADR-0004 相同：页面 settings 值 > `.env`；`.env` 作为默认来源每次加载实时读取（不落库），改 `.env` 重启即生效。`.env` 缺失 `PROXY` 键时启动报错并拒绝启动（与 ADR-0004 模型三键同机制，fail-fast）。

**为什么**：代理端口会随网络环境变化（已发生过 7981→7897），默认值硬编码在代码里意味着每次换端口都要改代码（且历史上发生过 `config.py` 与 `fetcher.py` 双源分叉，改了一处漏一处）。移入 `.env` 后换端口只改 `.env` 一处；同时 `fetcher.py` 构造器默认参数改为引用 `.env` 派生默认值，彻底消灭双源。

**考虑过的方案**：
- 并入 ADR-0004（修订为"模型+代理四键"）——被否：proxy 不是模型配置，语义不纯，且 ADR-0004 已定稿。
- `.env` 只放端口号（`PROXY_PORT`）——被否：换 IP 或协议（如 socks5）时不够用；完整 URL 与 DB 存储格式一致，合并逻辑零转换。
- 缺失时回退代码内置默认值——被否：静默回退掩盖配置缺失，与 ADR-0004 fail-fast 不一致。

**后果**：
- `STATIC_DEFAULTS` 不再含 `proxy`；默认值来源变为「静态项 + `.env`（模型三键 + PROXY）」。
- 前端页面不动：页面仍显示/编辑 DB 值，DB 无值时显示 `.env` 派生默认。
- 已落库的 `proxy` 页面值继续优先（本次改动不触碰 DB 数据）。
