# 任务成功后基线自动前移为持久进度游标

增量任务的下界是 `max(baseline, 已入库最大版本)`：正常运行时驱动增量的是已入库最大版本，baseline 只在「versions 表被清空」后作为恢复起点。我们决定：每次任务以 `ok` 完成且处理了至少一个版本时，把 settings 表的 `baseline_tag` 自动更新为本次处理的最大版本。

**为什么**：让 baseline 成为不依赖 versions 表的持久进度游标——即使 versions 表被清空，监控也从「上次分析到的版本」续接，而不是回落到默认 b11514 重放全部历史。

**考虑过的方案**：
- 新增独立的 `last_processed` 字段当游标，baseline 保持「首次运行起点」语义——被否：多一个键、页面多一个配置面，且两者在「清空 versions 后」语义完全重叠。
- partial 也算成功推进——被否：partial 表示部分版本未处理完，推进游标后这些版本的下界抬高，只能靠 `analyzed=0` 补分析兜底；ok-only 推进最保守，partial/failed 完全不动，由现有补分析机制保证不丢版本。

**后果**：
- baseline 从「用户设一次就固定」变为「任务成功时自动前移」，用户仍可在页面手动改；自动推进只严格递增（下界保证不会压过手动设的更大值、不会倒退）。
- 处理 0 个版本（无新 release）时不写库。
