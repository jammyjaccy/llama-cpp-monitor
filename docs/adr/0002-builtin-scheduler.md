# 内置 APScheduler 调度，而非外部 cron

任务调度由应用内置的 APScheduler 承担，随 FastAPI 进程运行；间隔在配置/页面中调整，手动触发直接调用内部 API。不依赖 Hermes cron 或系统任务计划程序。

**考虑过的方案**：Hermes cron 定时调 CLI（原监控任务的做法）。

**为什么内置**：用户要求「间隔可调 + 页面手动触发 + 页面看执行状态」三者闭环，内置调度让触发、状态、间隔都在同一进程内，页面操作即 API 调用，不依赖 Hermes 存活。代价：应用进程挂掉时任务停摆，由启动脚本/自启兜底（见 ADR-0003 的相关约定）。
